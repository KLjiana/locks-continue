# Locks Continue 难度与扩展系统设计指南

## 1. 文档目标

本文定义 Locks Continue 的锁难度、四种开锁小游戏、撬锁工具属性、锁词条、战利品表映射和服务端验证要求。

本阶段优先完成原生数据包驱动的难度系统。KubeJS 兼容不属于首期实现范围，但数据结构应保留后续接入空间。

## 2. 核心设计原则

1. 所有品质的撬锁器都可以尝试打开所有锁，不设置硬性品质门槛。
2. 难度主要改变小游戏本身的结构和操作要求，而不是单纯增加耐久消耗或减少失败次数。
3. 四种锁分别使用符合自身玩法的难度参数，不使用一个通用倍率强行控制全部小游戏。
4. 谜题由服务器生成种子并保存，客户端只负责显示、输入和动画。
5. 服务端负责验证位置、锁状态、工具、会话和关键游戏结果。
6. 同一个锁重复打开界面时不得重新随机出更容易的谜题，除非锁实例被重新生成或明确重置。
7. 数据包作者可以调整难度、战利品表规则、工具属性和词条，不需要修改 Java 代码。

## 3. 核心数据模型

每个已经生成的锁实例至少保存：

```text
containerPos       容器位置
lockType           锁类型
difficultyId       难度配置 ID
puzzleSeed         谜题种子
affixes            锁词条列表
generatedFrom      来源战利品表，可选
unlocked           是否已经解锁
```

每次开锁会话保存：

```text
sessionId          会话唯一 ID
playerId           玩家 ID
containerPos       目标容器位置
lockSnapshot       本局锁参数快照
toolSnapshot       开始时的工具及属性快照
puzzleState        服务端谜题状态
mistakesLeft       剩余有效失误次数
durabilitySpent    已消耗耐久
completed          是否完成
expiresAt          会话失效时间
```

难度和词条解析完成后必须生成不可变的 `LockChallengeSnapshot`。一局游戏开始后，即使数据包重新加载，也不能改变正在进行的谜题。

## 4. 五档默认难度

下表是首轮平衡建议，不是不可修改的硬编码值：

| 难度 | 弹子锁 | 记忆锁 | 圆盘锁甜蜜点 | 管道锁 |
| --- | --- | --- | --- | --- |
| 简单 | 4 个弹子 | 4×4 | ±12° | 5×5、1 个目标终端 |
| 普通 | 5 个弹子 | 4×4、预览更短 | ±9° | 5×5、2 个目标终端 |
| 困难 | 6 个弹子 | 6×6 | ±7° | 6×6、3 个目标终端 |
| 专家 | 7 个弹子 | 6×8 | ±5° | 7×7、4 个目标终端 |
| 大师 | 8 个弹子 | 8×8 | ±3° | 8×8、5 个目标终端 |

难度 ID 与显示名称分离，例如：

```text
lockscontinue:simple
lockscontinue:normal
lockscontinue:hard
lockscontinue:expert
lockscontinue:master
```

## 5. 弹子锁需求

### 5.1 玩法

- A/D 控制撬锁器横向移动。
- W 顶起当前撬锁器下方的弹子。
- 玩家需要在弹子到达顶部正确窗口时锁定弹子。
- 所有弹子锁定后成功。
- 操作失败时，根据难度和工具稳定性，掉落一定数量已经锁定的弹子。

### 5.2 难度参数

```json
{
  "pin_count": 7,
  "set_tolerance_ticks": 2,
  "apex_hold_ticks": 1,
  "speed_variance": 1.35,
  "reset_locked_pins": 2
}
```

- `pin_count`：弹子数量，建议限制为 3～10。
- `set_tolerance_ticks`：顶部判定前后的额外容错。
- `apex_hold_ticks`：弹子在最高点停留的时间。数值越大越简单。
- `speed_variance`：不同弹子的固定速度差异；带有 `variable_speed` 词条时，每次重试都会重新抽取速度。
- `reset_locked_pins`：一次有效失误会掉落的已锁定弹子数量。

### 5.3 实现要求

- 弹子数组和客户端槽位不得固定为 5。
- GUI 根据 `pin_count` 动态计算逻辑宽度。
- 超过 5 个弹子时，锁体中间区域使用平铺或分段绘制，不能拉伸整个贴图。
- 服务端保存每次弹起的确定性速度曲线和判定窗口。
- 无效或过期网络包不得被当成游戏失误，也不得损耗工具。

## 6. 记忆锁需求

### 6.1 玩法

- 开局展示全部卡牌一段时间。
- 展示结束后全部盖住。
- 玩家一次翻开两张牌。
- 配对成功时保持正面，配对失败时短暂停留后盖回。
- 所有卡牌配对完成后成功。

### 6.2 难度参数

```json
{
  "rows": 6,
  "columns": 8,
  "preview_ticks_per_pair": 4,
  "mismatch_limit": 5,
  "hint_count": 1
}
```

- `rows`、`columns`：棋盘尺寸，两者乘积必须为偶数。
- `preview_ticks_per_pair`：根据配对数量计算预览时间，避免大棋盘预览时间反而不足。
- `mismatch_limit`：允许的配对失败次数。
- `hint_count`：可提供的提示次数。

建议总预览时间使用：

```text
previewTicks = 基础时间 + 配对数量 × preview_ticks_per_pair
```

### 6.3 实现要求

- 服务端根据棋盘尺寸生成动态卡牌数组，不能固定为 16 张。
- 客户端根据行列数动态布局，8×8 时仍需保证物品图标可辨认和可点击。
- 每次选择第二张牌时，将两个索引发送给服务器验证。
- 按 `H` 消耗一次提示，提示只显示一个未完成对子 60 tick，并在状态栏显示剩余次数和倒计时。
- 服务端返回 `MATCHED`、`MISMATCH` 或 `REJECTED`。
- 只有 `MISMATCH` 可以扣除失误次数；`REJECTED` 表示无效输入或状态不同步。
- 随机物品池必须过滤空气、技术物品、无正常模型物品和不适合作为图标的物品。
- 后续可以增加“相似图标池”作为词条，不能作为所有高难度锁的默认行为。

## 7. 圆盘锁需求

### 7.1 玩法

- 撬锁器角度跟随鼠标，并限制在可操作圆弧范围内。
- 螺丝刀只跟随锁芯旋转，不跟随撬锁器角度。
- 撬锁器越接近隐藏正确角度，锁芯可以旋转得越远。
- 位于甜蜜点内时才能把锁芯完整转到开锁位置。
- 松开操作后锁芯平滑回弹。

### 7.2 难度参数

```json
{
  "sweet_spot_degrees": 5.0,
  "feedback_falloff": 1.5
}
```

- `sweet_spot_degrees`：正确角度容差，是圆盘锁的主要难度来源。
- `feedback_falloff`：离开正确角度后，可旋转范围下降的速度。

基础难度不需要复杂的压力系统。强转损耗、卡死和高摩擦更适合作为锁词条。

### 7.3 实现要求

- 正确角度必须位于客户端可以达到的角度区间。
- 服务器验证最终尝试角度和会话状态。
- 普通鼠标移动不发送高频网络包；只在正式尝试或必要同步时发送。
- 工具精度可以小幅扩大甜蜜点，但不能直接跳过谜题。

## 8. 管道锁需求

### 8.1 当前方案需要替换的原因

单条起点到终点的短路径不需要规划。随机加入与目标无关的假管道，只会增加画面噪声，并不会增加有效复杂度。十字管道旋转后形状不变，也不能计入谜题所需旋转次数。

### 8.2 新玩法目标

管道锁采用起点到终点的路线谜题：

1. 起点固定且不可旋转。
2. 根据难度生成一个或多个固定目标终点。
3. 起点必须同时连通全部目标终点才算成功。
4. 普通分支和无关管道不参与成功判定。
5. 非起点、非终点的单端叶节点改造成可旋转的直管、弯管或 T 型干扰管，不再大量留空。
6. 起点和全部目标终点连通后即可成功。

`require_all_connected` 和 `forbid_leaks` 仍保留为数据包的严格网络模式，
但内置难度默认关闭，避免普通分支重新影响路线谜题。

### 8.3 生成算法

1. 根据难度确定棋盘尺寸、填充格数和目标终点数量。
2. 使用随机深度优先搜索或随机 Prim 算法生成一棵连通树。
3. 选择边界叶节点作为起点，并按树上的真实路径距离选择终点；不能用曼哈顿距离代替路径长度。
4. 根据节点度数生成端点、直管、弯管、T 型和十字管。
5. 将非起点、非终点的单端叶节点替换成可旋转干扰管；高难度提高 T 型干扰管比例。
6. 先按难度区间定向打乱必经路线，再随机旋转路线外的干扰管道。
7. 单终点使用精确最低代价搜索；多终点计算共享生成树解的预计旋转量，并用每个终点的精确最短路线作为难度下界；不满足区间时重新生成。
8. 检查初始棋盘没有已经完成。

必须增加单向端点类型：

```text
END_CAP
```

### 8.4 难度参数

```json
{
  "width": 7,
  "height": 7,
  "terminal_count": 4,
  "minimum_solution_rotations": 18,
  "maximum_solution_rotations": 28,
  "minimum_route_cells": 24,
  "minimum_filled_cells": 47,
  "minimum_junctions": 10,
  "minimum_dead_ends": 0,
  "require_all_connected": false,
  "forbid_leaks": false,
  "hint_count": 1,
  "time_limit_ticks": 1200
}
```

`time_limit_ticks` 是管道锁的独立游戏限时，默认 `1200` tick（60 秒），允许 `20～7200`，`-1` 表示关闭难度限时。第一次合法旋转后开始计时，关闭界面或断线不会重置开始时间。服务端逐 tick 检查，达到上限即失败并只扣一次配置的失败耐久。

如果奖励规则使用 `time_ticks` 且 `failure_at` 为正数，则取该值与难度限时中较短的有效值。奖励规则的 `failure_at: -1` 只关闭奖励规则自身的时间限制；难度限时仍然生效。两处都设为 `-1` 才是不限时。界面倒计时使用服务端发来的实际剩余时间，与奖励评价指标分开同步。

复杂度主要由以下内容决定：

- 棋盘尺寸。
- 需要同时连通的目标终点数量。
- 最少非空格数量和可旋转干扰管密度。
- 起点到终点路线长度。
- T 型分叉数量。
- 空格和普通分支的干扰布局。
- 起点到终点在生成树上的真实路线长度。
- 单终点的实际最少旋转区间，或多终点共享解的预计旋转区间。
- 是否启用严格网络模式（仅数据包覆盖时生效）。
- 提示按 `H` 触发，每次消耗一次并显示 60 tick；提示目标来自当前棋盘到合法解的真实错误方向，不使用第一个泄漏口猜测。

计算最少旋转次数时必须考虑旋转对称性：

- 端点、弯管、T 型有 4 种方向。
- 直管只有 2 种不同方向。
- 十字管只有 1 种状态，不计旋转复杂度。

内置五档的默认管道区间为：

| 难度 | 棋盘 | 目标数 | 最少非空格 | 最少路线格 | 预计旋转区间 | 最少分叉 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 简单 | 5×5 | 1 | 20 | 7 | 2～5 | 1 |
| 普通 | 5×5 | 2 | 23 | 11 | 5～9 | 3 |
| 困难 | 6×6 | 3 | 34 | 17 | 11～17 | 6 |
| 专家 | 7×7 | 4 | 47 | 24 | 18～28 | 10 |
| 大师 | 8×8 | 5 | 62 | 32 | 28～42 | 14 |

未提供 `maximum_solution_rotations` 的旧数据包仍按无显式上限处理；生成器会采用靠近下限的目标区间，避免无意义地把棋盘打乱到极端难度。词条可以同时调整上下限、`minimum_route_cells` 和 `minimum_filled_cells`。

单终点棋盘使用精确最低旋转数。多终点棋盘使用生成树共享解的预计旋转数，并分别计算每个终点的精确最短路线作为难度下界；最难的单条目标路线不得低于预计旋转下限的约三分之一。这样能避免高密度多终点棋盘进行指数级整盘枚举，同时防止干扰管形成几次旋转即可绕过主路线的捷径。

## 9. 撬锁工具品质

任何品质的撬锁器都可以尝试任何难度的锁。品质只提供属性，不绑定特定锁类型。

建议属性：

```text
durability    总耐久
precision     操作精度
stability     稳定性
insight       解谜辅助能力
speed         客户端操作动画和响应速度
```

属性作用：

| 属性 | 弹子锁 | 记忆锁 | 圆盘锁 | 管道锁 |
| --- | --- | --- | --- | --- |
| precision | 扩大顶部窗口 | 无直接作用 | 小幅扩大甜蜜点 | 无直接作用 |
| stability | 减少失败时复位弹子 | 无直接作用 | 降低卡涩压力 | 无直接作用 |
| insight | 显示一次速度提示 | 临时显示一对牌 | 提供方向热度反馈 | 标记一处泄漏 |
| speed | 提升移动响应 | 加快翻牌动画 | 加快回弹动画 | 加快旋转动画 |

工具属性只能提供帮助，不能由客户端直接声明成功。

## 10. 锁词条

词条在基础难度参数解析完成后叠加，并保存进锁实例。建议首批词条：

| 词条 | 效果 |
| --- | --- |
| 多栓 | 弹子数量增加 1～2 个 |
| 紧簧 | 弹子顶部窗口缩短 |
| 迷雾 | 记忆锁预览时间缩短 |
| 复线 | 管道目标终端和分叉增加 |
| 锈蚀 | 错误操作的耐久损耗提高 |
| 卡涩 | 圆盘锁反馈下降更快 |
| 加固 | 增加有效失误所需的工具损耗 |
| 不稳定 | 失败后重置更多已有进度 |

词条不能直接修改客户端显示而不进入服务端快照，否则会造成客户端和服务器谜题状态不同步。

## 11. 战利品表与难度映射

世界生成容器初始化战利品表时，根据战利品表 ID 选择锁的难度、类型和词条。

规则建议包含：

```json
{
  "priority": 100,
  "loot_tables": [
    "minecraft:chests/ancient_city"
  ],
  "difficulty_weights": {
    "lockscontinue:expert": 70,
    "lockscontinue:master": 30
  },
  "lock_type_weights": {
    "lockscontinue:pin_lock": 25,
    "lockscontinue:pipe_lock": 25,
    "lockscontinue:rotary_lock": 25,
    "lockscontinue:memory_lock": 25
  },
  "affix_chance": 0.65,
  "maximum_affixes": 2
}
```

规则匹配顺序：

1. 容器明确指定的锁数据。
2. 优先级最高的精确战利品表规则。
3. 标签、命名空间或通配规则。
4. 默认规则。

同一个容器只能生成一次锁数据，区块重复加载时不得重新抽取难度和词条。

## 12. 网络与服务端验证

服务端至少验证：

- 玩家仍在目标容器附近。
- 目标区块已加载。
- 容器仍然存在并保持上锁。
- 玩家仍然持有开始会话时允许使用的撬锁工具。
- 会话未过期且尚未完成。
- 操作类型适用于当前锁。
- 操作序号和谜题状态没有过期。
- 成功条件由服务器谜题状态得出。

建议统一操作结果：

```text
UPDATED     合法操作，状态已更新
PROGRESS    合法并取得阶段进展
MISTAKE     合法操作但玩法判定失败，可以损耗工具
SOLVED      谜题完成
REJECTED    非法、过期或状态不同步，不损耗工具
```

只有 `MISTAKE` 可以扣除尝试次数或耐久。网络错误、重复包和过期包必须返回 `REJECTED`。

- 无效资源 ID 报告。

- 数据包重载日志。

## 14. 实施顺序

1. 将操作结果拆分为 `MISTAKE` 和 `REJECTED`。
2. 扩展难度定义、快照和网络序列化字段。
3. 将弹子锁改为动态弹子数量和动态 GUI。
4. 将记忆锁改为动态棋盘，并实现逐对服务端验证。
5. 使用完整网络规则重写管道生成器和完成判定。
6. 简化圆盘锁基础难度，只保留甜蜜点和反馈曲线。
7. 接入工具属性。
8. 接入锁词条。
9. 重新校准五档默认数据。
10. 完成数据包文档后，再考虑 KubeJS 接口。

## 15. 验收标准

### 通用

- 相同种子和快照在客户端与服务端生成相同谜题。
- 无效网络操作不会消耗工具。
- 重新打开同一个锁不会刷新谜题。
- 数据包配置错误不会导致服务器崩溃。

### 弹子锁

- 3～10 个弹子均可正常显示和操作。
- 所有弹子都能被服务端独立验证。
- 失败重置数量符合快照参数。

### 记忆锁

- 4×4、6×6、6×8 和 8×8 均可完成。
- 每次匹配由服务器验证。
- 不允许一次翻开三张牌或重复使用已匹配牌。

### 圆盘锁

- 所有目标角度都在客户端可达范围内。
- 五档甜蜜点宽度有明显但公平的区别。
- 撬锁器和螺丝刀矩阵互不影响。

### 管道锁

- 所有种子都能生成可解谜题。
- 初始状态一定未完成。
- 单终点达到配置的实际最低旋转区间；多终点达到共享解的预计旋转区间。
- 起点到终点的生成路线不少于 `minimum_route_cells`。
- 非空格数量不少于 `minimum_filled_cells`。
- 所有目标终点均可通过同一组管道朝向同时连通。
- 所有目标终端必须连通。
- 启用 `forbid_leaks` 时，任何泄漏都会阻止完成。
- 十字管不计入旋转复杂度。
